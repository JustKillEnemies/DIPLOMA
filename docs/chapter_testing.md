# Глава: Тестирование программного модуля интеграции MES

## 1. Цели тестирования
Цель тестирования - подтвердить работоспособность и устойчивость программного модуля интеграции MES при обработке производственных заданий.

В рамках тестирования решались следующие задачи:
1. Проверка корректности валидации входных данных.
2. Проверка безопасности доступа к API через ключ `X-API-Key`.
3. Проверка корректной работы HTTP-эндпоинтов.
4. Проверка логики отправки данных в Kafka.
5. Проверка конфигурации приложения в режимах `dev` и `prod`.

## 2. Инструменты и среда
Для автоматизации тестирования использовался фреймворк `pytest` и дополнительные библиотеки:
1. `pytest` - запуск и организация тестов.
2. `pytest-asyncio` - поддержка асинхронных сценариев.
3. `httpx` - зависимость для `FastAPI TestClient`.

Управление зависимостями выполнялось через `Poetry`.

## 3. Организация тестов
Тесты расположены в отдельной директории `tests/`:
1. `tests/test_models.py` - модульные тесты схемы `MESTask`.
2. `tests/test_config.py` - тесты конфигурации `Settings`.
3. `tests/test_api.py` - интеграционные тесты API (`/health`, `/api/v1/tasks`).
4. `tests/test_kafka_producer.py` - тесты сервиса отправки в Kafka.
5. `tests/conftest.py` - общие фикстуры и тестовые данные.

## 4. Покрытые сценарии
Реализованные проверки включают:
1. Успешную валидацию корректной MES-задачи.
2. Ошибки при некорректном `op_number`.
3. Ошибки бизнес-логики (`soaking_time_min > heating_duration_min`).
4. Ошибки температурной логики (`min_finish_temp_c >= target_temp_c`).
5. Граничные и недопустимые значения числовых полей.
6. Возврат `401`, если API-ключ отсутствует.
7. Возврат `403`, если API-ключ неверный.
8. Возврат `202`, если задача принята и отправка в Kafka успешна.
9. Возврат `500`, если отправка в Kafka завершилась ошибкой.
10. Проверку заголовка производительности `X-Process-Time`.
11. Инициализацию Kafka producer при успехе и при ошибке.
12. Поведение `send_task` при отсутствии producer и при исключении отправки.

## 5. Выполнение тестов
Команда запуска:

```bash
poetry run pytest
```

Фактический результат запуска от **29 апреля 2026**:

```text
21 passed in 3.22s
```

## 6. Вывод
Автоматизированное тестирование подтвердило корректную работу ключевых компонентов проекта: валидации входных данных, механизмов безопасности, API-слоя, конфигурации и интеграции с Kafka.

Полученный набор автотестов обеспечивает:
1. Быструю регрессионную проверку после изменений.
2. Снижение риска скрытых дефектов в бизнес-логике.
3. Повышение надежности и воспроизводимости работы системы.
